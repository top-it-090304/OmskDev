# Dungeon — особенности и «фишки» для презентации

Игровой и продуктовый слой: что показывать зрителю и как формулировать. Техническая база — в `01-architecture.md`.

---

## Главный посыл: **онлайн — это бомба**

Для презентации и защиты **вынесите сетевой кооп в топ-3 слайдов**, не «дополнением в конце». У вас не абстрактный «мультиплеерный режусчик», а **полноценная сессия по сети**: лобби, хост, синхрон одного и того же процедурного данжа у всех, общие этажи, общий провал при гибели союзника, серверный арбитраж урона, зеркалирование снарядов и лута. Это редкость для студенческого/инди rogue-like на Godot — **продавайте это первым абзацем и первым геймплейным роликом**.

**Короткие формулировки «с микрофона»:**

- *«Это rogue-like, который можно пройти вместе по сети — один хост, все видят одну и ту же карту.»*  
- *«Восемь человек в комнате, лобби, код подключения — и вы уже в одном данже.»*  
- *«Бой честный: сервер решает урон, карта не расходится между игроками.»*

## 1. Онлайн-кооп: что именно показать на слайдах и в демо

| Что демонстрировать | Почему это «вау» |
|---------------------|------------------|
| **Лобби** — список игроков, код комнаты, старт с хоста | Видно, что это настоящая сетевая сессия, не split-screen |
| **Два окна / два устройства** — один заходит гостем | Доказательство, что мир общий |
| **Одинаковая карта** у хоста и клиента | Синхрон `dungeon_state` с хоста — не «у каждого свой рандом» |
| **Удар по врагу с клиента** — HP и смерть совпадают | Авторитет сервера + реплика состояния врага |
| **Люк на следующий этаж** — оба переходят вместе | RPC кооп-перехода, общий темп забега |
| **Смерть одного** — game over у второго | Эмоция «мы команда», не соло с наблюдателем |
| **Подбор артефакта** — исчезает у обоих, без дюпа | Серверное решение + зеркалирование мира |

Дополнительно упомянуть устно: **ресинк данжа** если пакет потерялся; **втягивание в бой**, если один уже в комнате с врагами — остальных сервер подтягивает к бою.

## 2. Жанр и подача «в одном предложении» (если онлайн уже не первый слайд)

**Изометрический / топдаун rogue-like** с процедурной картой, боссами и мета-прогрессией — **плюс полноценный онлайн-кооп по ENet** (лобби, до восьми участников, общий данж и общая судьба партии). Мобильная сборка и тач — усиливают охват: **играть вместе можно и с телефона**.

---

## 3. Процедурная карта (после онлайна — «что именно синхроним»)

- Комнаты **старта**, **боя**, **босса**, **сокровищницы** из сцен-шаблонов — разнообразие + контроль качества.
- **Коридоры**, **препятствия**, **seed** — один забег = один согласованный мир для всей пати в онлайне.
- **Миникарта**, **сохранение этажа** — удобно для соло и для «отложили кооп на потом».

**Фраза для слайда:** «Процедурность не ломает кооп: карта генерируется на хосте и раздаётся всем как единое состояние.»

---

## 4. Бой и персонаж

- Статы, уровни, опыт, статусы (яд, отброс) — см. `GameConstants` / сейвы.
- В онлайне прогресс после левелапа может **реплицироваться на партию** — одна экономика на забег.

**Фраза для слайда:** «Соло — про билд; кооп — про билд + синхрон с союзниками.»

---

## 5. Враги и боссы (примеры для контента слайдов)

- **Goblin Axe**, **Goblin Slinger**, **Skeleton Bow**, **Beast Goblin**, **Skeleton King** — разные роли в бою; в коопе ИИ ориентируется на **ближайшую живую цель** среди всех игроков.

**Фраза для слайда:** «Враги давят на всю группу — не на одного экранного игрока.»

---

## 6. Артефакты и прогресс

- Рюкзак, попапы, сохранение имён артефактов.
- **В коопе подбор через сервер** — нет «двух одинаковых сокровищ» у двух клиентов.

---

## 7. Сокровищница и люк

- Колода предметов в сокровищнице; люк и этажи согласованы с сетевыми переходами.

## 8. Мобильный UX

- Mobile feature, виртуальные джойстики, сохранение раскладки.

**Фраза для слайда:** «Онлайн-кооп не привязан только к ПК: тот же забег с мобильного управления.»

## 11. Предложенная структура презентации (онлайн в начале)

1. Титул.  
2. **Ударный слайд: онлайн-кооп** — скрин лобби + подпись «один данж на всех, до 8 игроков».  
3. **Демо или два скрина** — хост + клиент, одна и та же комната / тот же босс.  
4. «Почему честно» — сервер, синхрон карты, общий game over (3–4 буллета).  
5. Процедурная карта / миникарта.  
6. Герой: статы + левелап.  
7. Враги и боссы (1–2 слайда).  
8. Артефакты / люк / этаж.  
9. Мобильность + языки.  
10. Технология (Godot 4.4, ENet) — см. `01-architecture.md`.  
11. Roadmap / Q&A.

Так зритель **сначала** запоминает дифференциатор («это реально по сети»), потом уже жанр и контент.

---

## 12. Честные оговорки (если спросят на защите)

- Подключение по **IP / коду комнаты** (из локального адреса хоста) — типичный сценарий **домашняя сеть / друзья по VPN / прямой IP**; отдельный матчмейкинг в облаке в коде не обязателен для того, чтобы называть режим **онлайн-мультиплеером**.  
- Лимит **7 гостей + хост** задан константой `MAX_CLIENT_PEERS`.
